This is an implementation from scratch of a Regular Expression parser and engine. When executed, the code reads an input regular expression and a string and checks if the string belongs to the language generated by the regular expression. The code uses two main blocks: a Recursive-Descent Parser and Finite Automatas. A more detailed explanation on this can be found in the bible for compilers ([1](#ref1)). This site is a summary of the project, therefore, the notation can be a bit confusing for a novel reader on compilers. Let us look at how the code works with an example. Consider the language that accepts numbers in binary that are multiples of 3. The following expression describes this language:

 ```
 (0|(1(01*0)*1))*
 ```

The code first recieves this string as input, and generates the following Abstract Syntax Tree:

<pre class="mermaid">
graph LR
    A(("*")) --- B(("|"))
    B --- C(("0"))
    B --- D(("·"))
    D --- E(("·"))
    D --- F(("1"))
    E --- G(("1"))
    E --- H(("*"))
    H --- I(("·"))
    I --- J(("·"))
    I --- K(("0"))
    J --- L(("0"))
    J --- M(("*"))
    M --- N(("1"))
</pre>

The advantage of this tree is that it represents the precedences of each operator. With this tree, we can generate the Non-Deterministic Finite Automaton (NFA) that describes the language. This is necessary to decide which strings belong to the language. The code then takes the AST and outputs the following NFA:

<pre class="mermaid">
graph LR
    A((A)) --->|ε| B((B))
    B --->|ε| C((C))
    C --->|1| D((D))
    D --->|ε| E((E))
    E --->|0| F((F))
    F --->|ε| G((G))
    F --->|ε| I((I))
    G --->|1| H((H))
    H --->|ε| G
    I --->|ε| J((J))
    J --->|ε| E
    J --->|ε| K((K))
    K --->|1| L((L))
    L --->|ε| O((O))
    O --->|ε| P((P))
    O --->|ε| B
    A --->|ε| P
</pre>

Once the NFA is built, now it suffices to "traverse" this graph by parsing an input string. If, we can start at the initial state (A) and reach state (P) by consuming the whole string and moving through the graph, we can affirm that the input string belongs to the language. The simulation of this is not straightforward. The other option is to convert the NFA into a Deterministic Finite Automata (DFA), which is much easier to traverse, since therea are no ε-transitions. A detailed explanation of another implementation can be found in [2](#ref2). The whole process however is explained in the textbook [1](#ref1).
